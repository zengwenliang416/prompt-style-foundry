# OnePic 前后端设计与代码规范

## 设计规范

### 前端

- 页面、状态、网络、存储和渲染分层；组件不直接拼接 API URL。
- 以任务组织界面：发现模板、检查提示词、上传单图、生成、查看本地记录。
- 明确显示单图约束、提示词版本、隐私边界以及 loading、空态、失败、重试、取消、过期状态。
- 支持键盘、焦点可见、语义标签、响应式布局和减少动态效果偏好。

### 后端

- Controller 只做协议转换和鉴权；Use Case 编排业务；Repository 隔离存储；Gateway 隔离供应商。
- API 资源使用名词、动作使用 HTTP 方法；长任务返回 `202` 和 job ID。
- 所有写操作支持幂等键；DTO 与数据库模型分离，禁止字段透传。
- 供应商差异只存在于 provider adapter，领域层使用统一能力模型。

## API 与数据

- JSON camelCase，数据库 snake_case；ID 使用 UUID/ULID；时间使用 UTC ISO-8601。
- 分页统一 cursor；响应统一 `{ data, error, meta }`。
- 错误使用稳定错误码，不依赖字符串匹配；新增字段可选，破坏性变化升级 API 版本。
- 大对象使用短期签名 URL，不把 base64 作为持久化接口。

## 前端代码

- ES modules、`const` 优先、窄作用域、显式错误处理。
- DOM、网络和 localStorage 访问集中在 adapter 函数。
- 禁止把 API Key、上传内容、完整提示词写入 console、URL 或遥测。
- 异步操作必须有 busy 状态、取消/超时和 `finally` 清理；重复提交由 UI 和幂等键双重防护。
- 按 4xx、429、5xx 和网络错误给出可理解提示。

## 后端代码

- 启用严格类型、格式化、静态检查和锁定依赖。
- 输入使用 schema 校验，输出使用显式 DTO；事务不跨越外部网络调用。
- 日志结构化且默认脱敏；数据库迁移可审计、可回滚，破坏性迁移分阶段执行。

## 测试门禁

- 单元：编译规则、状态机、策略、校验器。
- 集成：数据库、对象存储签名、队列、provider adapter。
- 合约：OpenAPI、错误码、分页、幂等语义。
- E2E：模板浏览、提示词查看、单图生成成功/失败/取消/过期。
- 安全：越权、重放、上传绕过、日志泄漏、限流、删除策略。

## Git 规范

小步提交，标题描述实际能力或修复，不混入无关格式化。API 契约、迁移、前端调用和测试作为同一变更计划联动；提交、推送、部署和切流分别授权和验证。
